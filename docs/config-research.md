# ModConfig 自定义与兼容调查

调查日期：2026-10-29。对象：当前 Organizer 0.1.5 与本机正式版 Managed DLL。本轮只调查，不修改玩法或部署新包。

## 已验证能力

- ModConfig.For / Define(bool,int,float,string) / DefineEnum / OnChanged 均存在。独立 `.local/config-probe` 编译通过，0 警告、0 错误；探针不加载、不部署。
- 本机 ModConfigWindow.BuildEntry 按类型生成开关、带范围滑条、choices/enum 下拉框、其他文本框。支持分组、提示、应用、恢复默认；没有现成组合键录入或颜色选择器。
- ConfigEntry.Set 会保存；ApplyValue 会触发 OnChanged。ModHook.OnModConfigApplied 在面板应用后提供统一刷新入口。需要跨字段校验，不能在几个 OnChanged 之间启用半套新绑定。
- RequiresRestart 是面板提示，不会自动延迟赋值；真正需要重启的项必须由 Mod 自己采用启动快照。建议大部分设置在当前点击/拖动结束后统一生效。
- ModConfig 使用 persistentDataPath/ModConfigs/<modId>.json，跨存档共用。适合玩家偏好，不保存当前目标容器、选区、半完成双击、当前物品标记开关等瞬时状态。
- KeyBindHelper 提供现有绑定查询及单键捕获；其 Define 私有。单个 KeyCode 枚举可作为 ModConfig 下拉选项，但并不是完整的组合键配置器。应持有自己的动作绑定，不改写游戏/其他 Mod 的绑定。
- Harmony.GetPatchInfo(method).Owners 在本机引用下编译通过，可报告共享补丁入口；共享入口不等于必然冲突，不能自动卸载别人的补丁。

资料：[开发指南·模组配置](https://github.com/dragonpan2/probably-stolen-modding/blob/main/ModdingGuide.zh-CN.md#模组配置)。文档与上述本机 IL 交叉核对；界面实际布局仍需进游戏验证。

## 建议第一版设置

| 分组 | 可自定义项 | 建议默认值 / 说明 |
| --- | --- | --- |
| 功能 | 快速转移、快捷固定、标签栏整理、风险标记分别启停 | 都开启；输入接管模式单独明确展示 |
| 按键 | 柜台转移、容器转移、固定、风险标记 | Shift+左键、Ctrl+左键、Alt+左键、双击 B；支持清除绑定 |
| 按键 | 左右修饰键是否等价 | 等价，维持现状 |
| 按键 | 整理跟随游戏绑定 / 独立绑定 | 跟随游戏整理键，当前默认 S |
| 手势 | 风险标记：单按切换 / 双击切换 / 按住显示 | 双击；间隔建议可调 0.15–0.8 秒，默认 0.35 秒 |
| 批量 | 点击选中项时批量操作 / 只操作点击项 | 同来源选区批量；不扩展到其他来源 |
| 目标 | 点击容器任意区域 / 仅标题栏来指定目标 | 任意区域，维持现状；提供仅标题栏避免误切换 |
| 目标 | 目标边框显示、目标改变提示 | 边框开启；提示可独立关闭 |
| 整理 | 记住最近原生菜单选择 / 使用固定偏好 | 记住最近选择；固定偏好可选大/小件优先、起始/末端 |
| 标记 | 赃物、违禁品分别显示；扫描嵌套内容 | 两类均开启，包含所有嵌套与分页 |
| 标记 | 扫描所有可见物品 / 仅自有物品 | 所有可见物品及其容器内容，维持现状；不意味着必被盘查发现 |
| 显示 | 赃物/违禁品/混合类别配色、边框粗细、透明度 | 黄/红/紫；先提供配色预设，可另加经校验的颜色文本 |
| 提示 | 转移结果：仅异常 / 全部 / 关闭普通提示 | 仅异常；不要与 F8 错误日志混成一个开关 |
| 配置 | 恢复默认 | 原生面板已有；按应用后生效，保留现有两个排序键以迁移旧偏好 |

以上是候选建议，不是已经实现的配置列表。按键应按动作命名而非“修改 Shift 的用途”：玩家改变的是柜台转移的触发键，销售柜台与外面交易台等对象身份保持明确。

## 兼容模式与冲突处理

推荐首先提供两种清楚的模式，避免多个布尔选项组合出“功能已关闭但原生输入仍被吞掉”的状态：

1. **助手接管（默认）**：保持用户已要求的行为，停用三个原生快速转移处理器，使用助手绑定。明确展示原生快捷转移处于停用状态。若某个动作解绑，其结果是不执行该动作，不悄悄回退到原生路线。
2. **原生转移＋辅助功能**：完全交还原生快速转移入口，同时停用助手转移/固定手势和拖动数量覆盖；保留独立整理与风险标记。这是遇到其他输入 Mod 冲突时的可选方案，不自动切换。

高级的“只在自己的组合键上接管”可以后续评估，但不能仅增加一个 `suppressVanilla=false`：当前输入路径仍会执行自定义动作，从而出现双重转移。它需要同时重构事件消费与状态清理。

冲突检查分层：

- **本 Mod 内部**：同一场景重复绑定、左右修饰键别名重叠、单按与双击共享键、转移键与半堆拖动键相互影响。必须明确拒绝或要求选择一种行为。
- **游戏可查询绑定**：KeyBindHelper、储藏协调器预设；提供冲突动作名称。接管模式下，被明确替代的原生快速转移绑定是预期重叠，不应误报成不可用。
- **硬编码按键**：本机已知 T、编辑器按键、开发菜单等需要上下文屏蔽和保留键清单。未知版本仍需重新核对。
- **其他 Mod**：共享 Harmony 方法可提示 Mod owner ID 供诊断；直接轮询输入、独立 Update、自定义 UI 或原生插件无法完整发现。没有“自动兼容全部 Mod”的可靠实现。

冲突默认处理建议：明确重叠的自定义动作暂不触发，并给出原因；不自动换键、不修改别人的设置、不卸载别人的补丁。提供只禁用冲突功能或选择原生模式的路径。

当前 `InputActionManager.Update` 前置补丁有时返回 false，会跳过原生分发；这属于结构性的兼容限制，单靠配置不能消除。长期应评估更窄的处理器级接管，并针对指定其他 Mod 组合测试。

## 不建议第一版开放的内容

- 任意“来源→目标”矩阵、自动选择另一个容器、满容量自动绕路：容易重新产生此前已修复的目标歧义。先开放动作按键和目标选择方式。
- 绕过固定、所有权、机器专用槽位、原生容量限制；关闭文字输入和模态保护：这些是正确性边界，不是普通偏好。
- 保存游戏对象引用、跨存档自动恢复目标容器、任意修改补丁顺序/优先级：不适合作为玩家选项。
- 每帧扫描开关和无限制刷新率：放高级区，提供有界的性能档位即可；当前 0.2 秒扫描与逐帧几何更新已分开。

## 建议实现顺序与验收

1. 固定配置 schema、默认值与输入模式；所有旧默认保持不变。
2. 普通 ModConfig 控件完成模块、行为、显示设置；按键捕获/冲突说明另作明确 UI。
3. 应用时整体校验绑定，空闲帧切换配置并清空旧手势。设置颜色/尺寸只刷新边框，不重置无关功能。
4. 按模块隔离失败；一个标记 UI 故障不应导致所有转移功能停用。游戏 API 不匹配时说明禁用模块及原因。
5. 测试重启持久化、升级保留设置、恢复默认、非法值、重复绑定、左右键、双击/单击冲突、拖动期间应用、模式切换后原生恢复、既有转移回归，以及实际其他输入 Mod 组合。

本轮没有改动或重新安装 0.1.5。探针编译仅证明接口可调用，不证明上述设置界面和兼容方案已经完成。
